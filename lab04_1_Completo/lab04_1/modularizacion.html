Modularización

Antecedentes

JavaScript se ha estandarizado en lo que se conoce como ES6 (ECMAScript 2015) Antes de eso no existia un estandar para generar modulos. Lo existente se convirtio en estandar de-facto (CommonJS, RequireJS, AMD).

Problema

Al programar JS se dividia el código en archivos que se concatenaban al generar la aplicación para producir un único archivo fuente. Esta práctica, podia generar varios problemas: colisiones de nombres entre archivos (por ejemplo: una misma variable global declarada en archivos distintos). multiples referencias al mismo archivo podían resultar en el mismo código siendo ejecutado varias veces

Solucion:

Se introduce el concepto de modulo como una unidad aislada:
  1. Cada modulo posee su propio scope lo que previene las colisiones de nombre.
  2. Cada modulo es una clase de tipo singleton que puede ser importado varias veces en distintos momentos.



Algunas formas de modularizar en JS:

  1. Expresión de función inmediatamente invocada (IIFE)

    Son funciones que se ejecutan tan pronto como se definen. 

                        (function () {
                        var nombre = "Pepito";
                      })();
                      // La Variable nombre NO es accesible fuera del ambito de la funcion
                      nombre; // Lanza una exception  "Uncaught ReferenceError: nombre is not defined"

  2. CommonJS (CJS)

    Es el sistema de módulos utilizado principalmente en Node.js antes de la introducción de los módulos ES. Los módulos CommonJS se cargan sincrónicamente, lo que significa que bloquean su ejecución hasta que se cargan. Esto es ideal para aplicaciones del lado del servidor, pero menos adecuado para código del lado del cliente, donde se prefiere la carga asíncrona.
    Sintaxis: CommonJS se utiliza require()para cargar módulos y module.exports/o exportsexportarlos. 

                        // Import
                    const fs = require('fs');
                   
                    // Export
                    module.exports = function () {
                      console.log("Hello from CJS");
                    };

  3. Definición de módulo asíncrono (AMD)

    Carga módulos y sus dependencias de forma asincrónica. Con origen en Dojo Toolkit, AMD está diseñado para aplicaciones del lado del cliente y no requiere herramientas adicionales. Solo requiere la biblioteca RequireJS, un cargador de módulos en el navegador. 

                    requirejs(
                    ["react", "react-dom"],
                    (React, ReactDOM) => {
                        ReactDOM.render(
                            React.createElement(
                                "p",
                                {},
                                "Greetings!"
                            ),
                            document.getElementById("root")
                        );
                    }
                );

    AMD no es tan popular como los formatos de módulos más modernos, como los módulos ECMAScript y la definición de módulo universal.

  4. Definición de módulo universal (UMD)

    ofrece una solución unificada para hacer que los módulos sean compatibles con muchos formatos de módulo diferentes, como CommonJS y AMD.

  5. Módulos ECMAScript (ESM)

    Los módulos ECMAScript (ESM), es la forma estándar y oficial de manejar módulos en JavaScript. Este formato de módulo se usa comúnmente en aplicaciones TypeScript.

    Al igual que CommonJS, ESM proporciona varias formas de exportar código: exportaciones predeterminadas o exportaciones con nombre. 

                        export function calcularArea() {
                        return Math.PI * Math.pow(radio, 2);
                      }
